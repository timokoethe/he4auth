# Feature documentation

Maintain one Markdown file per feature in `docs/features/` and use
`docs/features/_template.md` for new feature documents. Check and update the
corresponding feature document whenever an implementation changes the feature's
scope or observable behavior. Apart from the `status` frontmatter, keep feature
documents limited to `Purpose`, `User Story`, and `Acceptance Criteria`.

# Git operations

Do not create commits, push changes, or create or update pull requests. These
operations must always be performed by the user.
